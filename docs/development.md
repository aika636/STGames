## Как устроен ввод (Фаза 3)

`src/ui/input.js` не хранит состояние партии и ничего в ней не меняет — он только
превращает события браузера в вызовы обработчиков. Ход целиком делает `modal.js`: там
живут выделенная клетка, режим заметок и единственная точка проверки победы (`checkWin`).
Экранного ряда цифр 1–9 нет — цифры вводятся только с клавиатуры; под доской остались
счётчик оставшихся цифр (`createRemainingCounter()` в `board.js`) и четыре кнопки действий.

| Действие | Клавиатура | Мышь |
|---|---|---|
| Выбрать клетку | стрелки | клик (повторный — снять выделение) |
| Поставить/снять цифру | `1`–`9` | — (экранных цифр нет) |
| Стереть | `0`, `Delete`, `Backspace` | «Стереть» |
| Режим заметок | `N` / `Т` | «Заметки» |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z`, `Ctrl+Y` | «Отменить» / «Вернуть» |

Слушатель клавиатуры висит на `document` в фазе перехвата и отцепляется при закрытии окна.
Гасятся (`preventDefault` + `stopPropagation`) только **обработанные** клавиши — остальные
проходят к ST насквозь. Esc не перехватывается специально: его должен получить попап.
События из `select`/`input` внутри окна игры (селектор уровня) пропускаются без обработки.

## Установка в SillyTavern

Тестовая инсталляция — docker на `тестовом стенде`, UI `http://<тестовый ST>`.
Каталог расширений — per-user, он же единственный на смонтированном томе:

```
<SillyTavern>/data/default-user/extensions/Sudoku
```

`public/scripts/extensions/third-party` внутри контейнера использовать нельзя: он
обнуляется при обновлении образа.

```bash
./deploy.sh          # rsync рабочего дерева на тестовом стенде
```

Скрипт исключает `docs/`, `tests/`, `CLAUDE.md`, `.gitignore` и служебные каталоги —
в таверну уезжает только то, что грузит браузер. Внимание: rsync с `--delete` **не удаляет
исключённые файлы**, уже лежащие на хосте; если что-то попало туда раньше, убирать вручную.

После заливки — **хардрелоад вкладки** (Ctrl+Shift+R). Горячей перезагрузки расширений в ST нет.

## Тесты

Ядро — без зависимостей, свой раннер `tests/_harness.mjs`:

```bash
node --check index.js              # синтаксис без браузера
node tests/solver.test.mjs         # решатель + операции над сеткой (16 проверок)
node tests/generator.test.mjs      # генератор и сложность, 100 головоломок на уровень
node tests/generator.test.mjs 10   # быстрый прогон
node tests/game.test.mjs           # модель партии (22 проверки)
```

UI — под jsdom, единственная dev-зависимость:

```bash
npm install --no-save jsdom
node tests/ui.test.mjs             # доска, счётчик, окно, точки запуска (15 проверок)
node tests/input.test.mjs          # ввод: клавиатура, заметки, undo, победа (12 проверок)
```

`tests/input.test.mjs` держит один попап открытым на весь файл (сессия в `modal.js`
единственная) и решает сгенерированный пазл солвером ядра, а не заранее записанным
ответом — доска каждый раз новая.

Асинхронные тесты в файлах пишутся как `await test('...', async () => {...})` — раннер
возвращает промис только для них, и не дождаться его значит запустить тесты внахлёст.

## Отладка

* Все логи расширения идут с префиксом `[Sudoku]` — фильтр в консоли по нему.
* При загрузке в консоли должно быть `[Sudoku] vX.Y.Z загружен` и
  `[Sudoku] панель настроек инициализирована`.
* Состояние партии живёт в замыкании `src/ui/modal.js`; чтобы посмотреть его руками,
  проще открыть окно и дёргать функции из `src/core/game.js` в консоли, импортировав модуль
  по URL расширения.
* Настройки: `SillyTavern.getContext().extensionSettings.Sudoku`.

- [ ] Клик по кнопке открывает окно с доской 9×9; линии боксов толще внутренних.
- [ ] Подсказки видны, введённых цифр нет; таймер идёт.
- [ ] Смена уровня в селекторе генерирует новую доску и сохраняется в настройки.

- [ ] После закрытия окна ввод в чат снова работает, стрелки листают историю.
- [ ] Esc закрывает окно, а не только снимает выделение клетки.
- [ ] Стрелки в селекторе уровня переключают уровень, а не двигают выделение на доске.

## Известные подводные камни

* **Хоткеи ST.** Таверна вешает глобальные обработчики клавиатуры. Слушатель игры висит
  на `document` в фазе перехвата, живёт только пока открыто окно и гасит **только
  обработанные** клавиши (см. «Как устроен ввод»). В jsdom-тесте проверено, что цифра не
  доходит до `#send_textarea`; на живой инсталляции — пункт чеклиста выше.
* **rsync и исключения.** См. выше: `--delete` не трогает исключённые файлы.
* **Второе окно.** `openSudoku()` держит гвард `session`; две доски с одним состоянием
  разъехались бы.
