## Как устроен ввод (Фазы 3, 5)

`src/ui/input.js` не хранит состояние партии и ничего в ней не меняет — он только
превращает события браузера в вызовы обработчиков. Ход целиком делает `modal.js`: там
живут выделенная клетка, режим заметок и единственная точка проверки победы (`checkWin`).

Под доской — ряд цифр 1–9 (`createRemainingCounter(onDigit)` в `board.js`) и четыре кнопки
действий. Ряд цифр совмещает две роли: показывает, сколько каждой цифры осталось, и служит
экранным numpad'ом. Отдельного счётчика и отдельного numpad'а нет намеренно — на телефоне
это была бы лишняя строка, а на десктопе дублирование.

**Почему numpad обязателен:** в окне игры нет ни одного поля ввода, поэтому на мобильном
системная клавиатура не появляется вообще и цифру физически нечем поставить. Прятать ряд
за `@media (pointer: coarse)` не стали: на десктопе он всё равно нужен как счётчик.

| Действие | Клавиатура | Мышь / тач |
|---|---|---|
| Выбрать клетку | стрелки | клик (повторный — снять выделение) |
| Поставить/снять цифру | `1`–`9` | тап по цифре в ряду под доской |
| Стереть | `0`, `Delete`, `Backspace` | «Стереть» |
| Режим заметок | `N` / `Т` | «Заметки» |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z`, `Ctrl+Y` | «Отменить» / «Вернуть» |

Тап по цифре идёт через тот же `inputDigit`, что и клавиша, поэтому режим заметок,
авточистка пометок и undo работают для него одинаково. `mousedown` на ряду отменяется —
иначе кнопка забирала бы фокус у `.sudoku-root` и следующая клавиша уходила бы ей.

Слушатель клавиатуры висит на `document` в фазе перехвата и отцепляется при закрытии окна.
Гасятся (`preventDefault` + `stopPropagation`) только **обработанные** клавиши — остальные
проходят к ST насквозь. Esc не перехватывается специально: его должен получить попап.
События из `input`/`textarea`/`contenteditable` внутри окна пропускаются целиком. С
`select` уровня сложнее: попап ST при открытии сам фокусирует первый focusable-элемент
окна, и это как раз он, а игрок фокуса не видит (клик по клетке его не забирает —
`mousedown` отменён, чтобы не выделялся текст). Поэтому селектору отдаются только клавиши
навигации по списку (`SELECT_KEYS`), а цифры идут в игру. Дополнительно `.sudoku-root`
сделан фокусируемым (`tabIndex = -1`) и забирает фокус при открытии окна и при клике по
клетке. Симптом, который это лечит: до первого нажатия «Новая игра» цифры не ставились.

## Как сохраняется партия (Фаза 4)

`serializeGame(state)` кладётся в `settings.savedGame` из `persist()` в `modal.js` — после
каждого хода и при закрытии окна. Запись идёт через `saveSettingsDebounced()`, так что
серия быстрых ходов не превращается в серию записей на диск.

Таймер устроен так, что паузу засчитать нельзя: в состоянии лежат накопленное `elapsedMs`
и `startedAt` (момент последнего запуска), а `serializeGame()` сохраняет **только**
`elapsedMs`, посчитанное на момент сериализации. `startedAt` в сохранение не уходит вовсе,
поэтому при восстановлении отсчёт всегда начинается заново от накопленного времени. В
`closeSession()` важен порядок: сначала `pauseTimer()`, потом `persist()`.

Что восстанавливается: доска, пометки, время, уровень. Что нет: undo-стек (стек снапшотов
заметно раздувает `settings.json`, а undo после перезагрузки страницы был бы для игрока
неожиданностью), выделение и режим заметок.

Когда партия **не** восстанавливается, а начинается новая:

* уровень указан явно — `/sudoku hard`, селектор в окне, кнопка «Новая игра»
  (открытие без аргумента, включая кнопку в wand-меню, продолжает партию);
* сохранённая партия уже решена (`completedAt` проставлен);
* сохранение битое или от другой `STATE_VERSION` — `deserializeGame()` вернёт `null`.

## Статистика (Фаза 4)

`src/core/stats.js` — чистый модуль над простым объектом
`{ [difficulty]: { played, solved, bestTimeMs } }`, он же `settings.stats`. Записи
нормализуются при каждом чтении: `settings.json` игрок правит руками, и одно испорченное
поле не должно ронять панель настроек. `readEntry()` намеренно не создаёт запись в
объекте — иначе от одной только отрисовки панели в настройках копились бы пустые уровни.

Два решения, которые видно в цифрах:

* **«Сыграно» растёт в момент создания доски**, а не решения. Иначе брошенные партии
  нигде бы не отражались и «решено» всегда совпадало бы со «сыграно». Восстановленная
  партия повторно не считается — счётчик трогает только `startNewGame()`.
* **Считается заказанный уровень** (`state.difficulty`), а не оценённый генератором
  (`state.level`). Генератор умеет отдать ближайший уровень вместо запрошенного
  (`exact: false`), и партия уехала бы в строку, которую игрок не выбирал.

Учёт идёт через `countGame()` в `modal.js` — обёртка с `try/catch`: статистика это
побочная запись, её падение не должно ломать партию. Новый рекорд уровня `recordSolved()`
возвращает флагом, окно показывает его в тосте победы.

Панель настроек рисуется один раз при загрузке ST, поэтому окно игры зовёт `renderStats()`
после каждой засчитанной партии. Без панели в DOM (`settings.html` не загрузился) функция
молча ничего не делает. `resetStats()` чистит объект **на месте**: ссылку на него держит
`extensionSettings`, подменять новым нельзя.

## Установка в SillyTavern

Проверка идёт на отдельной docker-инсталляции ST 1.18.0.
Каталог расширений — per-user, он же единственный на смонтированном томе:

```
<SillyTavern>/data/default-user/extensions/Sudoku
```

`public/scripts/extensions/third-party` внутри контейнера использовать нельзя: он
обнуляется при обновлении образа.

```bash
./deploy.sh          # rsync рабочего дерева на тестовый ST
```

Скрипт исключает `docs/`, `tests/`, `CLAUDE.md`, `.gitignore` и служебные каталоги —
в таверну уезжает только то, что грузит браузер. Внимание: rsync с `--delete` **не удаляет
исключённые файлы**, уже лежащие на хосте; если что-то попало туда раньше, убирать вручную.

После заливки — **хардрелоад вкладки** (Ctrl+Shift+R). Горячей перезагрузки расширений в ST нет.

## Тесты

Ядро — без зависимостей, свой раннер `tests/_harness.mjs`:

```bash
node --check index.js              # синтаксис без браузера
node tests/solver.test.mjs         # решатель + операции над сеткой (16 проверок)
node tests/generator.test.mjs      # генератор и сложность, 100 головоломок на уровень
node tests/generator.test.mjs 10   # быстрый прогон
node tests/game.test.mjs           # модель партии (22 проверки)
node tests/stats.test.mjs          # статистика по уровням (8 проверок)
```

UI — под jsdom, единственная dev-зависимость:

```bash
npm install --no-save jsdom
node tests/ui.test.mjs             # доска, ряд цифр, окно, запуск, таблица статистики (19)
node tests/input.test.mjs          # ввод: клавиатура, тап, заметки, undo, победа (15 проверок)
node tests/persist.test.mjs        # сохранение партии, таймера и «сыграно» (10 проверок)
```

`tests/input.test.mjs` держит один попап открытым на весь файл (сессия в `modal.js`
единственная) и решает сгенерированный пазл солвером ядра, а не заранее записанным
ответом — доска каждый раз новая. `tests/persist.test.mjs`, наоборот, открывает и
закрывает окно несколько раз подряд: сохранение проверяется именно на стыке сессий.

Асинхронные тесты в файлах пишутся как `await test('...', async () => {...})` — раннер
возвращает промис только для них, и не дождаться его значит запустить тесты внахлёст.

## Отладка

* Все логи расширения идут с префиксом `[Sudoku]` — фильтр в консоли по нему.
* При загрузке в консоли должно быть `[Sudoku] vX.Y.Z загружен` и
  `[Sudoku] панель настроек инициализирована`.
* Состояние партии живёт в замыкании `src/ui/modal.js`; чтобы посмотреть его руками,
  проще открыть окно и дёргать функции из `src/core/game.js` в консоли, импортировав модуль
  по URL расширения.
* Настройки: `SillyTavern.getContext().extensionSettings.Sudoku`.

## Известные подводные камни

* **Хоткеи ST.** Таверна вешает глобальные обработчики клавиатуры. Слушатель игры висит
  на `document` в фазе перехвата, живёт только пока открыто окно и гасит **только
  обработанные** клавиши (см. «Как устроен ввод»). В jsdom-тесте проверено, что цифра не
  доходит до `#send_textarea`; на живой инсталляции — пункт чеклиста выше.
* **rsync и исключения.** См. выше: `--delete` не трогает исключённые файлы.
* **Второе окно.** `openSudoku()` держит гвард `session`; две доски с одним состоянием
  разъехались бы.
