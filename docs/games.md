# Контракт игры — как добавить свою мини-игру

STGames — платформа: ядро (оболочка, хаб, настройки, попап) общее, игры регистрируются
по контракту и получают от хаба всё остальное. Эта страница — полное описание контракта
и пошаговый рецепт на примере змейки. Тот же контракт, кратко, — в шапке `src/registry.js`.

## Объект игры

Игра — plain-объект, который передаётся в `register(game)` из `src/registry.js`. Реестр
проверяет контракт и **бросает Error при нарушении**, а не глушит ошибку fail-soft'ом:
сломанный модуль игры — ошибка программиста, её надо увидеть сразу при старте.

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | ✔ | Уникальный строковый ключ игры. Живёт в `STGames.games[id]` и в `data-game-id` плитки хаба |
| `title` | ✔ | Имя в списке игр и в шапке окна |
| `tagline` | — | Подпись под названием на плитке хаба |
| `icon` | — | Класс иконки Font Awesome, например `'fa-solid fa-worm'`. Хаб выводит её как `<i class="fa-solid …">` |
| `defaults` | ✔ | Plain-объект с настройками игры. **Замораживается** при регистрации — ни хаб, ни игра не должны менять дефолты на лету и делить состояние между партиями |
| `slash` | — | Объект `{ name, help, enumValues, parse }`; `name` — имя команды без ведущего `/`. Если поле есть, оболочка регистрирует `/name` → `openShell({ gameId, args })`. Необязательные: `help` (текст справки), `enumValues` (автодополнение аргумента), `parse(value)` → объект `args` |
| `mount(root, api)` | ✔ | Строит UI игры внутри `root` и возвращает `{ destroy() }` — и, если игре есть что перерисовывать при смене настроек, `{ destroy(), refresh() }` |
| `renderSettings(container, api)` | — | Рисует панель настроек игры в Extensions drawer |
| `renderStats(container, api)` | — | Рисует блок статистики игры в той же панели |

## api, который хаб передаёт в mount()/renderSettings()/renderStats()

| Поле | Что это |
|---|---|
| `settings` | Живой объект настроек игры — `game.defaults`, слитый с сохранёнными значениями (`getGameSettings`). Мутации прямо в нём: `settings.showGrid = true` |
| `save()` | Сохраняет настройки (и партию) на диск — `saveSettingsDebounced()` |
| `toast(kind, message)` | Короткое уведомление, `kind: 'info' \| 'success' \| 'error'` |
| `exitToHub()` | Закрывает игру и возвращает в список |
| `isSoloGame()` | `true`, если в реестре ровно одна игра. Оболочка тогда не показывает кнопку «← Игры»: список из одного пункта бесполезен. Сейчас игр восемь, поэтому возвращает `false` |
| `renderAllStats()` | Перерисовывает блоки статистики всех игр в панели настроек. Звать после каждой засчитанной партии |
| `onSettingsChanged()` | Сообщает оболочке, что настройки изменились: она зовёт `refresh()` открытого экрана. Нужен в `renderSettings` — переключатель в панели должен действовать на идущую партию, а не со следующей |
| `args` | (только в `mount`) Объект аргументов из слэш-команды — результат `game.slash.parse(value)` |

## Жизненный цикл

```
register(game)          — проверка контракта, заморозка defaults
    ↓
openShell({gameId})     — попап + корень .stg-root (topbar, «← Игры», экран)
    ↓
game.mount(root, api)   — игра строит свой DOM в root, вешает слушателей,
                          возвращает { destroy() }
    ↓
… игра живёт, игрок играет …
    ↓
refresh()               — (необязательный) оболочка зовёт, когда игрок поменял
                          настройки в панели: экран перечитывает их и
                          перерисовывается, не дожидаясь следующего хода
    ↓
destroy()               — хаб зовёт при выходе «← Игры», при закрытии попапа и при
                          падении mount. Игра обязана снять всех слушателей,
                          остановить таймеры/rAF и сохранить партию.
```

`destroy()` вызывается в `finally` закрытия попапа гарантированно: сохранение партии
судоку живёт в `destroy()` игры, потерять его нельзя. Поэтому он должен быть идемпотентным
и не бросать исключений (оболочка всё равно ловит).

## Что оболочка берёт на себя

Игре **не нужно** ничего из этого — это уже сделано в `src/shell/`:

- **Попап.** `callGenericPopup` с `POPUP_TYPE.DISPLAY` (окно без кнопок, крестик, закрытие
  по Esc), с фолбэком на собственный оверлей `.stg-overlay`, если попапа в этой версии ST
  нет. Одно окно на всё расширение: гвард от второго попапа.
- **Хаб.** Список зарегистрированных игр плитками (иконка, `title`, `tagline`); последняя
  открытая игра подсвечивается (`lastGame`). Клавиатуру хаб не перехватывает: Esc должен
  достаться попапу.
- **Точки запуска.** Кнопка «STGames» в wand-меню, `/stgames`, и `/имя_игры` из
  `game.slash` — регистрируются оболочкой.
- **Настройки и статистика.** Общая панель в Extensions drawer: по блоку на игру,
  `renderSettings`/`renderStats` зовутся с контейнером и api. `renderAllStats()`
  перерисовывает статистику всех игр после каждой партии.
- **Фокус.** Корень `.stg-root` фокусируемый (`tabIndex = -1`) и забирает фокус при
  открытии и кликах: попап ST при открытии сам фокусирует первый focusable-элемент, и без
  этого им оказывается какой-нибудь select игры.
- **Верхняя строка.** Кнопка «← Игры» (прячется, если игра в реестре одна), заголовок —
  `game.title`.

## Правила для новой игры

1. **`core/` — без DOM и без SillyTavern.** Чистые функции над данными, тестируемые под
   `node` без браузера: движок, правила, статистика. Всё, что трогает `document` или
   `getContext()`, — только в `ui/`.
2. **Слушатели снимаются в `destroy()`.** Всё, что игра повесила на `document`, `window`
   и чужие элементы, обязано сниматься. Оболочка снимает только свои слушатели; то, что
   осталось висеть, утекает в следующую игру или в чат.
3. **Esc не перехватывать.** Его должен получить попап и закрыть окно целиком. Игра не
   должна ни обрабатывать Esc, ни звать `stopPropagation` на нём.
4. **Глушить только обработанные клавиши.** Слушатель клавиатуры — на `document` в фазе
   перехвата, живёт только пока открыто окно; `preventDefault()` + `stopPropagation()`
   только на клавишах, которые игра реально съела. Всё остальное проходит к ST насквозь —
   иначе сломаются хоткеи таверны, а цифры змейки не должны уезжать в поле ввода чата.
5. **Fail soft.** Падение статистики, тоста или отрисовки панели не должно ронять партию:
   оборачивать побочные записи в `try/catch` (оболочка тоже ловит, но свой `catch`
   дешевле).
6. **CSS-префикс.** Все классы игры — с префиксом `id` игры: `.snake-*`, `.sudoku-*`.
   Оболочка и хаб — `.stg-*`. Никаких голых селекторов тегов: таверна и соседние
   расширения не должны ломать игру, а игра — их.
7. **Отложенная работа проверяет, жив ли экран.** Оболочка игру не ждёт: `unmount()`
   синхронный и вызывается немедленно — при «← Игры», при выборе другой игры и в
   `finally` закрытия попапа. Всё, что уходит в `setTimeout` / `requestAnimationFrame` /
   промис, обязано первым делом проверить локальный флаг «экран уничтожен» и выйти,
   ничего не нарисовав: колбэк, уже ушедший в очередь макрозадач, `clearTimeout` не
   отменяет, и он писал бы в вырванный из DOM экран. Сам `destroy()` — **идемпотентный**:
   его зовут дважды (выход в хаб плюс закрытие попапа), повторный вызов должен молча
   выйти. Образец — `src/games/reversi/ui/game.js` (флаги `destroyed` / `thinking`),
   тест на это — в `tests/reversi/ui.test.mjs`.
8. **Сохранять партию в `destroy()` — до того, как чистить свой корень.** Другого шанса
   записать состояние у игры не будет: закрытие окна не должно стоить игроку партии.
9. **Данные игра вправе грузить асинхронно, но `mount()` остаётся синхронным.** Тяжёлые
   данные (словарь «Слов» — четверть мегабайта) незачем тащить с каждой загрузкой таверны:
   их берут динамическим `import()` при первом открытии. Оболочка при этом ждать не умеет
   и не будет, поэтому `mount()` **сразу** возвращает `{ destroy() }` и рисует заглушку
   («Загружаю…»), а колбэк загрузки живёт по правилу 7: первой строкой проверяет
   `destroyed`. Промис стоит кэшировать на уровне модуля, но **неудачную** загрузку —
   выбрасывать из кэша, иначе одна сетевая осечка ломает игру до перезагрузки страницы.
   Образец — `src/games/words/ui/game.js` (`loadDictionary()`).

## Рецепт «добавь свою игру» (на примере змейки)

1. **Папки.** `src/games/<id>/core/` (чистая логика), `src/games/<id>/ui/` (DOM),
   `src/games/<id>/index.js` (объект игры).

2. **Ядро.** Движок и статистика — функции над данными, без DOM. У змейки:
   `core/engine.js` (`createSnake`, `setDirection`, `step`, `speedMs`) и `core/stats.js`
   (`readStats`, `recordPlayed`, `recordResult`, `resetStats`). Сразу пишутся тесты под
   `node` — `tests/<id>/engine.test.mjs`.

3. **Объект игры** в `index.js`:

   ```js
   export default {
       id: 'snake',
       title: 'Змейка',
       tagline: 'Аркада: ешь, расти, не врезайся',
       icon: 'fa-worm',
       defaults: Object.freeze({ stats: {}, showGrid: false }),
       slash: { name: 'snake' },
       mount(root, api) { return createSnakeScreen(root, api); },
       renderSettings(container, api) { /* чекбокс «Показывать сетку» */ },
       renderStats(container, api) { /* сыграно / лучший счёт / лучшая длина */ },
   };
   ```

4. **`mount(root, api)`.** Чистит `root` (`root.innerHTML = ''`), ставит класс корня,
   строит DOM, вешает слушателей, заводит `requestAnimationFrame`-цикл, возвращает
   `{ destroy() }`. Ключевые детали змейки: пауза при `visibilitychange`/`blur`,
   запись результата строго один раз за заезд (`recordResult` + `api.save()` +
   `api.renderAllStats()` + тост рекорда), «сыграно» растёт в момент старта заезда.

5. **`destroy()`.** Отменяет rAF, снимает клавиатуру/d-pad/свайпы и слушатели окна,
   чистит `root.innerHTML`.

6. **Регистрация.** В корневом `index.js`:

   ```js
   import myGame from './src/games/<id>/index.js';
   // ...
   register(myGame);
   ```

   После этого игра появляется в хабе, в панели настроек, у неё есть `/имя` — и её
   подхватывает всё написанное выше: попап, фокус, статистика.

7. **UI-тест** (`tests/<id>/ui.test.mjs`, jsdom): хаб показывает плитку, `mount` строит
   экран, управление меняет состояние, `destroy()` снимает слушатели. Запуск всего:
   `node tests/run.mjs`.
