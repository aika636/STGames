# Roadmap — расширение Sudoku для SillyTavern

## Рамки проекта

**Sudoku** — клиентское UI-расширение SillyTavern: полноценная игра в судоку в модальном окне
поверх чата.

Принятые решения (зафиксированы до начала разработки):

| Вопрос | Решение |
|---|---|
| Роль LLM | **Никакой.** Чистая мини-игра, персонаж не участвует, чат не затрагивается |
| Размещение UI | **Модальное окно** поверх чата |
| Источник головоломок | **Локальная генерация в JS**, без наборов готовых пазлов |

Из этого следует главное упрощение: расширение **не читает и не пишет `ctx.chat`**, не трогает
рендер сообщений и не делает сетевых вызовов. Единственная точка соприкосновения с ST —
кнопка запуска, попап и `extensionSettings` для сохранения партии.

## Целевое окружение

* SillyTavern **1.18.0** (docker-инсталляция для тестов).
* Каталог установки — per-user: `<SillyTavern>/data/default-user/extensions/Sudoku`.
  Именно он лежит на смонтированном томе; `public/scripts/extensions/third-party` внутри
  контейнера обнуляется при обновлении образа.

## Конвенции (унаследованы от соседнего расширения Imaginy)

* **Без сборки.** Plain ES-модули + CSS, загружаются браузером напрямую. Никаких бандлеров,
  TypeScript и runtime-зависимостей от npm.
* **Без бэкенда.** `server-plugin/` не нужен.
* **Доступ к ST только через `SillyTavern.getContext()`**, не через относительные импорты
  `../../../../script.js`. Контекст **не кэшируется** в переменной модуля — запрашивается
  заново в каждой точке использования.
* **Namespace везде:** `MODULE_NAME = 'Sudoku'`, CSS-классы `sudoku-*`, настройки в
  `ctx.extensionSettings.Sudoku` (camelCase `extensionSettings`, не `extension_settings`).
* **Fail soft.** Любая ошибка внутри игры логируется с префиксом `[Sudoku]` и не роняет UI
  таверны. Хуки оборачиваются в try/catch.
* **`event_types` vs `eventTypes`:** обращаться через хелпер
  `ctx.event_types ?? ctx.eventTypes ?? {}` и пропускать подписку, если имени события нет.
* Любое предположение о внутренностях ST (имена полей, событий, DOM-классов) проверяется на
  живой инсталляции и записывается в `docs/sillytavern-api.md` с версией ST.

## Структура репозитория

```
manifest.json          # display_name: Sudoku, js/css, loading_order 100, requires: []
index.js               # тонкая точка входа: кнопка запуска, инициализация настроек
src/ctx.js             # getContext()/event_types-хелпер, toast()
src/log.js             # логи с префиксом [Sudoku]
src/settings.js        # DEFAULT_SETTINGS + merge-on-load, биндинг settings.html
src/core/rng.js        # mulberry32 + shuffle: воспроизводимый рандом для тестов
src/core/grid.js       # чистые операции над сеткой: индексация, юниты, конфликты
src/core/solver.js     # backtracking-солвер + countSolutions(limit) для единственности
src/core/rate.js       # оценка сложности логическими техниками (одиночки/locked/пары)
src/core/generator.js  # полное решение + выкалывание клеток по уровню сложности
src/core/game.js       # модель партии: given/value/notes, undo-стек, победа (DOM-free)
src/core/stats.js      # статистика по уровням: сыграно / решено / лучшее время
src/ui/modal.js        # попап поверх чата (callGenericPopup + фолбэк на свой оверлей)
src/ui/board.js        # рендер сетки 9×9, подсветка, применение состояния
src/ui/launcher.js     # кнопка в wand-меню и слэш-команда /sudoku
src/ui/input.js        # мышь/тач/клавиатура, режим заметок, кнопки действий
style.css              # все стили под префиксом .sudoku-
settings.html          # панель в Extensions drawer
tests/*.test.mjs       # node-тесты чистой логики (src/core/*)
docs/*.md              # документация
deploy.sh              # rsync на тестовый ST (не в git)
```

`src/core/` не знает о DOM и о SillyTavern — только чистые функции над данными. Это делает
самую сложную часть (генератор) тестируемой под `node` без браузера.

Отдельного `src/persist.js` в итоге не появилось: сохранение партии — это три функции
рядом с сессией в `modal.js`, а всё, что можно было вынести в чистое ядро, лежит в
`game.js` (`serializeGame`/`deserializeGame`) и `stats.js`.

## Фазы

### Фаза 0 — Скелет и деплой

Каркас расширения, который загружается в ST и ничего не делает.

* `manifest.json`, тонкий `index.js`, `src/ctx.js`, `src/log.js`, `src/settings.js`,
  `settings.html`, `style.css`.
* `deploy.sh` — rsync рабочего дерева в per-user каталог расширений тестового ST.
* `.gitignore`, `CLAUDE.md`, каркас `docs/`.

**Готово, когда:** расширение видно в списке Extensions на живой таверне, в консоли есть
`[Sudoku] v0.1.0 загружен`, панель настроек отрисована в drawer.

### Фаза 1 — Ядро игры (чистый JS, без DOM) — **сделано**

Самая содержательная часть; полностью покрывается тестами под `node`.

1. **Solver** (`src/core/solver.js`) — backtracking с выбором клетки минимальных кандидатов
   (MRV); занятые цифры хранятся в 9-битных масках строк/столбцов/боксов. Отдельная
   `countSolutions(grid, limit)` с ранним выходом на втором найденном решении.
2. **Generator** (`src/core/generator.js`) — заполнение пустой сетки тем же солвером со
   случайным порядком перебора цифр даёт полное валидное решение; затем **выкалывание**
   клеток в случайном порядке с откатом, если решение перестаёт быть единственным.
   Центральная симметрия включена для всех уровней, кроме expert.
3. **Сложность** (`src/core/rate.js`) — головоломка решается человеческими техниками, и
   уровень выдаётся по тому, до какой техники пришлось дойти: tier 1 — naked/hidden single,
   tier 2 — locked candidates (pointing/claiming), tier 3 — naked/hidden pair. Итог —
   максимум из «уровня по технике» и «уровня по числу подсказок» (≥38 → easy, ≥32 → medium,
   ниже → hard). **Expert выдаётся только за нехватку техники** — за головоломку, которую не
   берут ни одиночки, ни locked candidates, ни пары. Шкала по числу подсказок сама по себе
   до expert не поднимает: иначе «экспертом» становилась бы любая разреженная сетка,
   решаемая одними одиночками (при 25 подсказках — примерно каждая четвёртая).

**Сделано.** `node tests/generator.test.mjs` — 100 генераций на каждом уровне, все валидны,
с единственным решением и в заказанном уровне. Замеры на рабочей машине:

| Уровень | Ср. время | Макс. | Подсказок | Попыток в среднем |
|---|---|---|---|---|
| easy | 0.4 мс | 1.5 мс | 41–42 | 1.00 |
| medium | 0.4 мс | 1.5 мс | 33–34 | 1.07 |
| hard | 0.9 мс | 4.9 мс | 28–31 | 1.22 |
| expert | 7.1 мс | 32.1 мс | 25–28 | 3.16 |

Бюджет «<100 мс на головоломку» выдержан с запасом, весь прогон из 400 головоломок — ~1 с.
Риск «генерация expert подвисает» закрыт: фоновая предгенерация не понадобилась.

### Фаза 2 — Доска и модалка — **сделано**

* `src/core/game.js` — модель партии (значения, пометки, undo/redo, таймер, конфликты,
  сериализация). Сделана раньше плана: доске нужно что-то рендерить.
* `src/ui/board.js` — сетка 9×9 на CSS Grid; DOM строится один раз, `render()` только
  переставляет классы и текст. Границы боксов рисуются по data-атрибутам, а не
  nth-child-селекторами. `aria-label` на каждой клетке.
* `src/ui/modal.js` — окно игры: заголовок (уровень, таймер, «Новая игра»), доска,
  строка статуса. Попап через `ctx.callGenericPopup(..., POPUP_TYPE.DISPLAY)` —
  окно без кнопок, с крестиком и закрытием по Esc. Фолбэк на собственный оверлей
  `.sudoku-overlay`, если попапа в этой версии ST не окажется. Гвард от второго окна.
* `src/ui/launcher.js` — кнопка в wand-меню (`#extensionsMenu`) и слэш-команда
  `/sudoku [уровень]` через `SlashCommandParser` с фолбэком на устаревший
  `registerSlashCommand`.
* Таймер идёт уже сейчас (по плану был в Фазе 3) — без него заголовок выглядел сломанным.

Проверенные API таверны записаны в `docs/sillytavern-api.md`.

**Сделано** на уровне кода и автотестов: `node tests/ui.test.mjs` (jsdom) — 14 проверок,
включая построение доски, подсветку, оба пути показа окна и обе ветки регистрации команды.
**Визуально в браузере пока не проверено** — нужен хардрелоад таверны.

### Фаза 3 — Взаимодействие — **сделано**

* `src/ui/input.js` — модуль ввода: он не знает про состояние партии, а только превращает
  события браузера в вызовы обработчиков (`onDigit`, `onErase`, `onMove`, `onToggleNotes`,
  `onUndo`, `onRedo`). Ход целиком делает `modal.js`.
* **Клавиатура:** цифры 1–9, `0`/`Delete`/`Backspace` — стереть, стрелки — движение
  выделения (не перепрыгивает на соседнюю строку и не выходит за край), `N` (и `Т` на
  ЙЦУКЕН) — режим заметок, `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` — undo/redo.
* **Мышь/тач:** клик по клетке выделяет её, повторный клик — снимает; `mousedown` гасится,
  чтобы фокус не уезжал в чат и не выделялся текст при быстром вводе.
* **Панель под доской** — строка «сколько каждой цифры осталось» (выставленные до конца
  гаснут, но не исчезают: строка не должна дёргаться по ширине) и кнопки
  «Заметки / Стереть / Отменить / Вернуть». Экранного ряда цифр 1–9 нет: он занимал
  половину окна, а цифры вводятся с клавиатуры.
* **Подсветка** — выбранная клетка (рамкой) и все клетки с той же цифрой. Строка, столбец
  и бокс не заливаются: сплошная подсветка трёх юнитов забивает доску сильнее, чем
  помогает её читать.
* **Тема таверны** подхватывается автоматически: акцент и линии — из переменных ST
  (`--SmartThemeQuoteColor`, `--SmartThemeBorderColor`), а все заливки считаются
  `color-mix`'ом от `currentColor`, поэтому окно одинаково читается на тёмных и светлых
  темах. Для браузеров без `color-mix` каждое такое правило дублируется фолбэком.
* **Победа** фиксируется в одном месте (`checkWin`): `complete()` останавливает таймер,
  статус меняется на «решено за MM:SS», доска подсвечивается, дальнейшие ходы не проходят.

**Подводный камень (закрыт кодом, ждёт проверки в браузере):** слушатель клавиатуры висит
на `document` в фазе перехвата и живёт только пока открыто окно; на каждую *обработанную*
клавишу зовётся `preventDefault()` + `stopPropagation()`. Необработанные клавиши проходят
насквозь — чужие хоткеи ST не ломаются. Esc специально не перехватывается: его должен
получить попап и закрыть окно.

**Сделано** на уровне кода и автотестов: `node tests/input.test.mjs` (jsdom) — 12 проверок,
включая сквозной прогон «доска пройдена до конца только клавиатурой» (пазл читается из DOM,
решение считает солвер ядра) и проверку того, что цифра не доходит до `#send_textarea`.
Проверено в браузере на живой инсталляции; правки после первого прогона — убраны
экранные цифры и подсветка юнитов, доска переведена на переменные темы.

### Фаза 4 — Персистентность и настройки — **сделано**

* ✅ Текущая партия (пазл, решение, ввод игрока, заметки, время) в
  `ctx.extensionSettings.Sudoku` + `ctx.saveSettingsDebounced()`. Undo-стек **не**
  сохраняется: снапшоты раздувают `settings.json`, а undo после перезагрузки страницы был
  бы для игрока неожиданностью.
* ✅ Настройки: уровень по умолчанию, подсветка конфликтов, автоудаление заметок, таймер.
* ✅ Статистика: сыграно / решено / лучшее время по уровням (`src/core/stats.js`, таблица
  в панели настроек). «Сыграно» считается по началу партии, уровень берётся заказанный —
  почему именно так, в шапке `stats.js`.

**Готово, когда:** закрытие вкладки на середине партии и повторное открытие восстанавливает
доску ровно в том же состоянии. — Выполнено, покрыто `tests/persist.test.mjs` и
`tests/stats.test.mjs`; детали — `docs/development.md`, разделы «Как сохраняется партия»
и «Статистика».

### Фаза 5 — Полировка

Мобильная вёрстка, тёмная и светлая темы ST, доступность (`aria-label` на клетках,
видимый фокус), ручной чек-лист в `docs/development.md`.

Сделано: экранный ряд цифр под доской (на мобильном системной клавиатуры нет — вводить
было нечем), размер доски ограничен и по ширине, и по высоте экрана, чтобы окно целиком
помещалось на телефон, оформление сетки облегчено (боксы отличаются цветом линии, а не
толщиной). Осталось: проход по доступности и ручная проверка на живом телефоне.

## Риски и митигации

| Риск | Митигация |
|---|---|
| ~~Генерация «expert» подвисает из-за проверок единственности~~ | **Закрыт в Фазе 1:** худший замер — 32 мс на головоломку. Лимит попыток (`DEFAULT_ATTEMPTS = 30`) и фолбэк на ближайший уровень (`exact: false`) остались как страховка: генератор не возвращает null и не зацикливается |
| Хоткеи ST перехватывают ввод цифр | **Закрыт кодом в Фазе 3:** слушатель на `document` в фазе перехвата, живёт только пока открыто окно, гасит только обработанные клавиши. Тест проверяет, что цифра не доходит до `#send_textarea`. Осталось подтвердить на живой инсталляции |
| CSS таверны и других расширений ломает сетку | Префикс `.sudoku-` на всём, изоляция контейнера, никаких голых селекторов тегов |
| `callGenericPopup` ведёт себя иначе, чем ожидалось | Собственный оверлей как фолбэк заложен с самого начала |

## Оценка

~4–5 дней работы. Критический путь — Фаза 1 (генератор) и Фаза 3 (ввод).

## Открытые вопросы

* Нужен ли режим «проверить решение» / подсказка по клетке, и не убивает ли он интерес.
* Хранить статистику per-user глобально или per-chat.
* Нужны ли размеры сетки кроме 9×9 (4×4 для детей, 16×16) — пока вне рамок.
