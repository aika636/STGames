# Тесты и проверка

## Юнит-тесты

Раннер `tests/run.mjs` собирает все `*.test.mjs` под `tests/` и гоняет каждый отдельным
процессом (jsdom-тесты вешают на процесс глобальные `window`/`document`/`SillyTavern`).

```bash
node --check index.js        # синтаксис без браузера
node tests/run.mjs           # все тесты, итог «N файлов, M упало»
node tests/run.mjs <игра>    # фильтр по папке: sudoku, snake, reversi, words,
                             # minesweeper, nonogram, crossword, balda, doodlejump, shell
```

Ядро — без зависимостей, UI — под jsdom (единственная dev-зависимость:
`npm install --no-save jsdom`; без неё UI-файлы падают на импорте, раннер подсказывает,
как доставить). Асинхронные тесты пишутся как `await test('…', async () => {…})`.
`toast()` из `src/ctx.js` зовёт амбиентный `toastr`, поэтому в jsdom-тестах подменяют
`globalThis.toastr`, а не `ctx.toastr`.

Тест соперника реверси («сложный уровень обыгрывает лёгкий») вероятностный и может
изредка падать сам по себе — повторный запуск обычно проходит.

## E2e (живая таверна и браузер)

jsdom не отвечает на вопрос «работает ли в настоящей таверне»: попап ST, его хоткеи, фокус,
запись настроек на диск, размеры и `aspect-ratio`. Этим занимается прогон под Playwright.

```bash
npm install --no-save jsdom playwright   # обе dev-зависимости ставятся вместе:
npx playwright install chromium          # без package.json npm вычищает «лишнее»
export STGAMES_ST_DIR=/путь/к/SillyTavern
node tests/e2e/run.mjs                   # весь прогон
node tests/e2e/run.mjs games             # фильтр по имени файла набора
node tests/e2e/run.mjs --headed          # с видимым браузером
node tests/e2e/run.mjs --fresh           # снести data-root и начать с чистого ST
```

Устройство (`tests/e2e/_st.mjs`):

* поднимается **отдельный** SillyTavern (`--port`, `--dataRoot <temp>`, `--listen false`,
  `--browserLaunchEnabled false`); LLM-бэкенд не нужен;
* каталог расширения внутри data-root — симлинк на корень репозитория, тесты гоняют
  рабочее дерево как есть; data-root переживает прогоны (кэш сборки фронтенда ST), а
  состояние расширения обнуляет сам тест (`resetSettings`);
* готовность — появление `#stgames_wand_button`;
* один запуск ST и один браузер на весь прогон; наборы `*.e2e.mjs` экспортируют
  `default async (env)`; в `tests/run.mjs` они не попадают;
* `e2eTest()` на падении кладёт скриншот в `tests/e2e/.artifacts/`;
* «сохранил» в e2e значит «дождался ответа на `POST /api/settings/save`»
  (`flushSettings()`), иначе `reload()` обгоняет запись.

Наборы: `games` (загрузка без ошибок в консоли, хаб, монтирование и ввод каждой игры,
партии, переживающие перезагрузку; ввод кодами клавиш EN-раскладки; росчерк настоящей
мышью; живой rAF-цикл дудл джампа), `shell`, `mobile` (раскладка и размеры на телефонных
форматах). `tests/e2e/doodle-sweep.mjs` — автопилот дудл джампа (`docs/doodlejump.md`).

Грабли прогона:

* **Копия расширения в каталоге ST перебивает симлинк.** Если в
  `public/scripts/extensions/third-party/STGames` лежит копия, ST грузит её, а расширение
  из data-root молча пропускает как дубль. Прогон идёт, но проверяет старый код.
  `_st.mjs` падает с внятным сообщением; лечится удалением копии из каталога.
* **Чужие расширения** показывают попапы посреди прогона и перехватывают клики: гасить
  скриптом, закрывая `dialog.popup[open]` без `.stg-root` внутри (Escape закрыл бы и
  окно игры).
* **Порт после убитого прогона** может остаться занятым.
* **Проверка наложений у кроссворда неустойчива:** головоломка берётся из пула случайно,
  от неё зависят высота раскладки и длины слов, а замер может попасть в анимацию
  появления попапа. Падение `crossword` в мобильном наборе без наложения на скриншоте не
  считать регрессом.

## Отладка

* Логи расширения идут с префиксом `[STGames]`. При загрузке в консоли
  `[STGames] vX.Y.Z загружен` и `[STGames] панель настроек инициализирована`, при миграции
  — `[STGames] настройки перенесены из Sudoku в STGames`.
* Настройки: `SillyTavern.getContext().extensionSettings.STGames.games.<id>`.
* Состояние партии судоку живёт в замыкании `src/games/sudoku/ui/game.js`; проще дёргать
  функции `src/games/sudoku/core/game.js` в консоли, импортировав модуль по URL
  расширения.
* После обновления файлов расширения — хардрелоад вкладки (горячей перезагрузки
  расширений в ST нет).

## Установка для ручной проверки

Каталог расширений per-user: `<SillyTavern>/data/<user>/extensions/STGames`. Достаточно
скопировать (или слинковать) туда рабочее дерево без `docs/`, `tests/` и служебных файлов
— браузер грузит только `manifest.json`, `index.js`, `src/`, `style.css`, `settings.html`.
Чеклист ручной проверки — `docs/manual-check.md`.
